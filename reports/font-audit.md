# EasyCV 字体检查记录

检查日期：2026-09-10。检查对象为仓库字库、Windows Edge 实际使用的字体、中文字形栅格结果和导出 PDF。

## 为什么之前切换字体，中文没有变化

Inter、Outfit、Roboto、Manrope、DM Sans 和 JetBrains Mono 不含完整中文字形。原界面把这些西文字体放在主选项中，中文继续使用相同的后备黑体，所以部分选择只有英文变化。现在主选项均包含中文；旧西文组合只在读取旧简历时保留兼容入口。

| 主选项 | 中文与字重 | 加载方式 |
|---|---|---|
| Noto Sans SC | 中文可变无衬线，100–900 字重 | 本地常用字分组优先，其余 Unicode 区段补齐 |
| 鸿蒙黑体 | 现有文件包含 29,063 个 cmap 映射，仅常规字重；粗体由浏览器合成 | 沿用本地 WOFF2 |
| 未来荧黑 | 简体中文无衬线，常规/粗体，每个原始字体包含 32,227 个 cmap 映射 | 常用字分组、西文/标点包和生僻字包分开加载 |
| 未来荧黑 · 紧凑 | 独立的 Condensed 字形，常规/粗体，中文与英文同时变化 | 同上；使用真实字形，不对文字做 CSS 缩放 |
| 系统黑体 | 中文与西文随设备系统变化 | 无额外字体下载 |

四个内置选项的纯中文 Canvas 栅格结果各不相同。另通过浏览器实际使用字体接口确认 Noto Sans SC、Glow Sans SC Normal 和 Glow Sans SC Condensed 的字体来源为本地自定义字库，且中文字形使用了对应的字体。没有只检查 CSS 名称就认定成功。

## 兼容与排版

- 原有西文字体资源保留。旧链接、JSON 备份、A/B 方案继续接受原 font 标识和 cjkFont 搭配，不自动改写已有简历。
- 新建方案采用内置中文字体，切换字体保留字号、行高、页边距、板块顺序等参数。
- 原先缺失的 NotoSansSC-Regular.woff2 引用已由实际存在的 Noto Sans SC 字库替代。
- PDF 导出等待字体加载完成。系统字体和极少数后备字形仍可能随设备变化；需要固定投递版式时使用 PDF。
- 未来荧黑缺少的个别字符由 Noto Sans SC 和系统字体后备，不用空白方框代替正文。

## 资源检查

仅按 512 个 Unicode 码点拆包，会让常用汉字分散到较多文件。现在把 GB2312 汉字按 256 字一组优先组织，西文/标点独立，保留其他字形覆盖。字体选择按钮本身使用界面字体，浏览选项不会提前下载所有字库。

在同一份默认简历、本地 Edge 冷缓存测试中，Noto Sans SC 默认页面资源由约 6.82 MB 降至最终版本约 2.74 MB，减少约 60%；其中字体约 1.76 MB、23 个字体资源。中间版本的 2.38 MB 统计尚未包含最终未来荧黑 CSS 目录，交付以最终版本为准。这是传输字节比较，不是公网加载时间承诺。实际请求取决于简历字符与所选字重。系统字体不需要额外字库请求。

所有运行时资源均本地提供，无新增框架或外部字体服务。新加入的未来荧黑附项目原始 OFL 许可证，字形分片保留名称与许可元数据。

## 来源与更新

- [Noto Sans SC 官方源](https://github.com/google/fonts/tree/main/ofl/notosanssc)，OFL 1.1。
- [未来荧黑 v0.93 官方发行版](https://github.com/welai/glow-sans/releases/tag/v0.93)，[字体许可](https://github.com/welai/glow-sans/blob/master/OFL.txt)。项目代码的 MIT 许可与字体 OFL 许可分别处理。
- 鸿蒙黑体沿用项目已有文件，本次没有替换源文件或引入新的发行包。
- scripts/vendor_sans.py 更新 Noto Sans SC 与既有西文字体；scripts/vendor_chinese.py 更新未来荧黑；scripts/common_cjk.py 提供常用字分组逻辑。下载源文件缓存于 artifacts/font-sources，不纳入仓库。
